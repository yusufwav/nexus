## 1. WHAT THIS IS

**Nexus** — a study platform for first-year Computer Science students at
Nelson Mandela University (NMU). It sells notes per module, and gives the
reader a study partner ("the tutor") that reads the same notes they do.

There are **two applications** and **one server**:

| | Where | Stack |
| --- | --- | --- |
| **Web** | `C:\Users\yusuf\orca\projects\nexus` | Next.js 16 (App Router), React 19, TypeScript |

| **Server** | the web app's `/api/*` routes + `packages/db` | Next.js route handlers, Drizzle ORM, PostgreSQL |

The mobile app is a **port of the web app**, not a separate product. It talks
to the same deployed server and the same database. It has no server of its

## 3. THE SECURITY MODEL — READ THIS BEFORE TOUCHING ANYTHING

This is the part that is easy to break and expensive to get wrong. The
codebase documents its reasoning in comments; the reasoning is deliberate.

### 3.1 Two database roles, and they are not interchangeable

| Role | Used for | Can |
| --- | --- | --- |
| **owner** (`neondb_owner`) | migrations, `db:push`, RLS scripts, `grant-purchase.mjs` | everything |
| **`nexus_app`** | the web request — this is what `DATABASE_URL` points at on Vercel | `SELECT/INSERT/UPDATE/DELETE` on a named set of tables. **No DDL. No `BYPASSRLS`. No `CREATE ROLE`. No `supabase_vault`.** |

**`nexus_app` is `NOBYPASSRLS` on purpose.** Every RLS policy is inert unless
the connecting role is subject to RLS. The local `postgres` role carries
`BYPASSRLS`, so RLS was proven to actually bind rather than assumed to.

**Migrations run as the owner connection string, never as `nexus_app`.**

### 3.2 The reader identity is a session GUC, not a connection

`packages/db/src/reader.ts`:

- `withReader(db, fn)` — runs `fn` in a transaction with
  `app_reader_id()` set to the reader's id.
- `withSystem(db, fn)` — runs `fn` **without** a reader identity, for work
  that legitimately is not per-reader (the catalogue, the modules).

**Every per-reader query must go through `withReader`.** A query that runs
outside it sees no reader, and RLS will refuse it — which is the correct
outcome, not a bug to work around.

### 3.3 Rate limiting — two systems, deliberately different

| | Better Auth `rateLimit` | `consumeAiBudget` (`packages/db/src/ai-rate-limit.ts`) |
| --- | --- | --- |
| Guards | credential endpoints | the tutor's AI spend |
| Storage | database (survives restart) | database (survives restart) |
| On failure | **fails CLOSED** (`disableMemoryFallback: true`) | **fails OPEN for the reader's own key**, closed for the server's |
| Why | "the limiter broke" must never mean "no limit" — that is a password-guessing oracle | failing closed costs an honest reader a 429 on their own money |

**Do not unify them.** The asymmetry is intentional and is commented as such.

Tighten `customRules` further only with care: sign-in is 5/min, sign-up is
5/hour.

### 3.4 The read budget is a DELAY, not a refusal

`packages/db/src/read-budget.ts` — `GET /api/topics/[slug]` is correctly gated
(purchase required) but nothing resisted *repetition*. The fix is a **delay**
(20 free requests/min, then +250ms per request, capped at 6s), not a 429:

- a 429 catches honest readers with a defence aimed at a different crime, and
  there is no way back — the account is simply broken;
- refusal is free for a scraper to retry, so it buys no time;
- delay costs a naive loop minutes instead of seconds.

**This does not prevent anyone.** It buys attribution. Do not describe it as
prevention.

### 3.5 The origin guard is two layers

`apps/web/src/lib/origin-guard.ts` + `trustedOrigins` in `packages/auth`.

`trustedOrigins` is a **strict allowlist**. There is deliberately no wildcard
and no "trust whatever Origin the request carries" fallback — that would
silently reduce the check to no check at all.

`BETTER_AUTH_EXTRA_ORIGINS` exists **for LAN testing only**. It is not in
`.env.schema` on purpose (so varlock does not complain when it is absent),
and setting it in production prints a loud warning on every cold start.
**Unset it on the deployed environment.**

### 3.6 The mobile app's credential

The mobile app sends **both**:

- `Authorization: Bearer <session token>` — the `bearer` plugin turns it back
  into a session cookie server-side, so everything downstream is the same code
  path the website uses.
- `Cookie: <session cookie>` — so the app works against a server that does not
  have the bearer plugin yet.

It also sends `Origin: <server url>`, because React Native's `fetch` sends
`Origin: null` and Better Auth's CSRF check refuses that. This is an
assertion about who the client is, checked against the allowlist — not a way
around the check.

**The mobile app never receives `DATABASE_URL`.** A React Native bundle ships
inside the `.ipa`/`.apk` where anyone can read it.

### 3.7 Provider keys (BYOK) are sealed

`provider_keys` holds the reader's own model-provider keys, encrypted. There
is a dedicated test script: `packages/db/scripts/test-key-isolation.mjs`.
Never write a provider key to a log, a response body, or an error message.

**The mobile app only uses `/api/auth/*` today.** Everything else it does

### 4.1 The 4xx/5xx contract the mobile app depends on

From `src/lib/auth-client.ts` in the mobile app — **do not change these
shapes without changing that file at the same time**:

```
POST /api/auth/sign-in/email  { email, password }
  -> 200 { redirect, token, url, user }  + Set-Cookie: <session cookie>
  -> 4xx { message, code }               e.g. INVALID_EMAIL_OR_PASSWORD

POST /api/auth/sign-up/email  { name, email, password }
  -> 200 { token, user }                 + Set-Cookie: <session cookie>
  -> 4xx { message, code }               e.g. PASSWORD_TOO_SHORT

GET  /api/auth/get-session
  -> 200 { session, user }
  -> 200 null                            (not signed in)

POST /api/auth/sign-out      -> 200 { success: true }
```

- The 4xx body is **FLAT** — `{ message, code }` at the top level, **not**
  nested under `error`.
- The `message` is written for the reader and is shown to them verbatim.
- A **5xx body is never shown to the reader** — it can carry internal detail
  (a driver error naming the database host). The client replaces it.
- `minPasswordLength` is **12** on the server. The mobile app mirrors this
  number so it can say so up front.

## 5. THE TUTOR — THE EXPENSIVE PART

`/api/ai` is the most expensive thing in the app to leave open: every call
is a real model invocation billed to whoever holds the key, and with BYOK a
refused or substituted call still lands on the server's account.

The model resolution order (`apps/web/src/lib/tutor-model.ts`):

1. the reader's own provider key and chosen model (BYOK) — they pay;
2. the server's own key — the owner pays, so it is budgeted.

`consumeAiBudget` is checked **immediately after** `resolveTutorModel`,
because the source is not known any earlier. The budget is 20 turns per
60s window per reader, and a degraded counter (unreachable table) is
survivable for the reader's own key and **not** for the server's.

Email verification is enforced **on AI messages, not on the site**. A
verified mailbox cannot mint an unbounded number of accounts against the
budget. Browsing, the catalogue and buying are unaffected.

The tool loop runs **on the device** in the mobile app (four steps is the
ceiling) and on the server in the web app.

### 11.4 THE MATHS IS TYPESET BY THE APP

The tutor's answers can contain LaTeX, and `src/lib/latex/` + `src/components/Math.tsx`
typeset it **natively** — a symbol table, a parser and a box-layout engine
that draw with `<Text>` and `<View>`. There is **no KaTeX and no WebView**.

The reason is a React Native limitation, not a preference: a nested
`<Text>` is a **span** (`TextProps` does not extend `ViewProps`), so it
cannot be transformed or repositioned — a superscript cannot be raised
inside a paragraph and a fraction cannot be built out of one. The unlock is
that the app's face is **monospace**, so every width is arithmetic and
nothing has to be measured on the device.

Two consequences worth knowing:

- **The font's repertoire is checked at build time.** JetBrains Mono is
  missing fifteen maths characters, and every command that needs one has a
  documented fallback, because a missing glyph renders as a **box**.
- **A `$` span that does not look like maths is a dollar sign.** A price
  written `$50` would otherwise open a formula that never closes.

### 11.5 HOW A CHANGE IS LOOKED AT

There is no device in the loop. `scripts/preview-*.mjs` render a screen to a

the thing it previews. `npm run preview:latex` does the same for the maths,
and `LATEX_SCALE=2.4` draws it big enough to read.
